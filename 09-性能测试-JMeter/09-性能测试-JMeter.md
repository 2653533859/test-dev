# 09-性能测试-JMeter

工具只占三成，压测建模和结果分析才是核心。会点 JMeter 按钮不等于会性能测试。

## 学习目标

- 能根据业务量推算出压测模型（并发数、TPS 目标、think time、场景配比）
- 熟练用 JMeter 完成脚本录制、参数化、关联、断言、集合点
- 看得懂聚合报告的每一列，能判断瓶颈在应用、数据库还是中间件
- 输出一份结论明确的性能测试报告，而不是一堆截图

## 计划覆盖的知识点

- 概念：性能测试 / 负载测试 / 压力测试 / 稳定性测试 / 容量测试的区别
- 核心指标：并发用户数、TPS 与 QPS、响应时间（平均值为什么不可靠，要看 P95 / P99）、错误率、资源利用率
- 压测模型：目标 TPS 推算、二八原则估算峰值、递增加压与阶梯加压、思考时间
- JMeter 组件：线程组（普通 / setUp / tearDown、阶梯加压插件）、HTTP 请求、HTTP 信息头管理器、Cookie 管理器
- 参数化：CSV Data Set Config、用户定义变量、函数助手（`__Random`、`__time`、`__counter`）
- 关联：正则表达式提取器、JSON 提取器、跨线程组传值
- 断言与监听器：响应断言、JSON 断言、聚合报告、察看结果树（压测时必须关闭）
- 逻辑控制器、定时器（固定 / 高斯 / 同步定时器做集合点）
- 执行方式：GUI 只用于调试，压测用命令行 `jmeter -n -t -l -e -o`；分布式压测
- 监控与分析：JMeter + InfluxDB + Grafana、服务端资源监控、JVM 与 GC、慢 SQL、日志定位
- 调优思路：定位瓶颈的顺序（压力机 → 网络 → 应用 → 中间件 → 数据库），常见瓶颈与对策

## 常考点

- 并发用户数、TPS、响应时间三者的关系
- 为什么看 P95 / P99 而不是平均响应时间
- 压测结果 TPS 上不去、响应时间变长，你怎么一步步定位
- 压测时发现瓶颈在压力机自己，有哪些表现
- GUI 模式压测为什么不准
- 稳定性测试要压多久，观察什么指标
