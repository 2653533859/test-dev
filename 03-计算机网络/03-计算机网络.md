# 03-计算机网络

接口测试、抓包分析、性能问题定位的理论前提。不需要背协议细节，但要能解释一次请求从发出到返回经历了什么。

## 学习目标

- 讲清一次 HTTPS 请求的完整链路：DNS → TCP → TLS → HTTP → 响应
- 看得懂 Wireshark / Fiddler 抓到的包，能据此判断问题在客户端、网络还是服务端
- 遇到超时、连接被拒、证书报错，能定位到具体环节

## 计划覆盖的知识点

- 分层模型：OSI 七层与 TCP/IP 四层，各层典型协议
- TCP：三次握手与四次挥手、可靠传输机制、滑动窗口、TIME_WAIT 与 CLOSE_WAIT 堆积
- UDP 与 TCP 的取舍
- HTTP：请求与响应结构、常用方法、状态码分类、常见请求头与响应头
- HTTP/1.1 长连接、HTTP/2 多路复用、HTTP/3 简介
- HTTPS：对称与非对称加密、证书链、TLS 握手过程、抓包需要装根证书的原因
- Cookie / Session / Token / JWT 的区别与适用场景
- DNS 解析过程与本地 hosts、CDN 对测试的影响
- 跨域与 CORS、代理与反向代理
- 抓包工具：Wireshark、Fiddler、Charles、mitmproxy

- 301 与 302、401 与 403、502 与 504 的区别
