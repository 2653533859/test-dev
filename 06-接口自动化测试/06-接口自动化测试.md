# 06-接口自动化测试

投入产出比最高的自动化层，建议在 Web / App 自动化之前先做扎实。

## 学习目标

- 能独立看懂接口文档并设计出完整的接口用例（正常、异常、边界、鉴权、幂等）
- 用 requests 封装出可复用的请求层，处理好鉴权与会话保持
- 断言不止查状态码：结构校验、字段校验、数据库校验三层都要做
- 会用 Mock 解耦上游依赖，让用例能稳定跑

## 计划覆盖的知识点

- 工具链：Postman 手工验证与调试、Apifox / Swagger 文档、抓包补充文档缺失的字段
- requests：`get` / `post`、`params` / `data` / `json` 的区别、headers、文件上传、超时与重试
- 会话与鉴权：`Session` 保持 Cookie、Token 与 JWT 的获取与刷新、签名鉴权（sign 计算）
- 用例设计：单接口用例、接口串联（依赖参数提取与传递）、业务流场景用例
- 断言体系：状态码、响应结构（JSON Schema）、关键字段值、数据库落库校验、日志校验
- 数据驱动：YAML / Excel 管理用例数据，动态参数与关联提取（JSONPath / 正则）
- Mock：`unittest.mock`、`responses`、独立 Mock 服务、契约测试概念
- 加密与解密接口的处理、文件上传下载接口、WebSocket 接口测试思路

## 常考点

- 接口测试要设计哪些维度的用例（不要只说正常和异常）
- 接口之间有依赖，登录 Token 和上游返回的 ID 怎么传递
- `data` 与 `json` 参数的区别，Content-Type 分别是什么
- 只断言状态码有什么问题，你的断言分几层
- 接口返回加密数据 / 带签名校验，自动化怎么做
- 上游服务不稳定或还没开发完，你的用例怎么跑
