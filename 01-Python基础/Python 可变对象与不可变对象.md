# Python 可变对象与不可变对象

![[assets/object-model.svg]]
*图示：变量是「名字→对象」的绑定（id/type/value）；可变对象原地修改 id 不变，不可变对象「赋值即换新对象」。*

> 一切皆对象，变量只是“名字→对象”的绑定。搞不懂“可变/不可变”和“引用语义”，后面深浅拷贝、默认参数、函数传参、哈希全都会踩坑。这一篇从对象模型底层讲起。

## 概念

### 1. Python 的对象模型：id / type / value

Python 中**每个数据都是对象**，对象有三要素：

- `id(obj)`：对象在内存中的身份（CPython 里就是内存地址），生命周期内不变
- `type(obj)`：类型，决定支持哪些操作
- `value(obj)`：值

“变量”不是装数据的盒子，而是一个**名字（label）**，通过绑定（binding）指向一个对象。赋值 `a = x` 的含义是：让名字 `a` 指向 `x` 所指向的那个对象，而不是把 `x` 复制一份。

```python
import sys
a = [1, 2, 3]
b = a
print(id(a) == id(b))        # True，a 和 b 指向同一个对象
print(sys.getrefcount(a))    # 引用计数（含临时引用，会比你以为的大 1）
```

### 2. 可变（mutable） vs 不可变（immutable）

划分标准是：**对象创建后，能不能在不改变 `id` 的前提下原地修改其内容。**

| 类别 | 类型 | 能否原地改 | 示例 |
|---|---|---|---|
| 不可变 | `int` `float` `str` `tuple` `frozenset` `bytes` `bool` `None` | 否 | `s.upper()` 返回新串 |
| 可变 | `list` `dict` `set` `bytearray` 以及自定义类实例 | 是 | `lst.append(1)` 改原列表 |

为什么 `str` 不可变？因为字符串被广泛用作字典的键、被多个引用共享，`s[0] = 'x'` 若允许原地改，所有引用 `s` 的地方都会莫名变化，还会破坏哈希缓存。不可变带来：可哈希、可安全共享、可驻留（intern）。

### 3. 不可变对象的“修改”到底是什么

对不可变对象做“修改”，Python 不会改原对象，而是**创建一个新对象，再把名字重新绑定过去**：

```python
s = "abc"
print(id(s))          # 例如 1402...
s = s + "d"
print(id(s))          # 变了！s 现在指向一个新字符串对象
```

这就是为什么字符串拼接在循环里用 `+=` 会很慢——每轮都新建字符串、拷贝内容。大量拼接要用 `list.append` 再 `''.join()`。

### 4. 函数传参：call by object reference（共享传参）

Python 的求值策略官方称为 **“call by sharing / call by object reference”**：把实参对象的**引用**传进去。效果：

- 函数内对**可变对象原地修改**，调用方看得见（因为大家指向同一对象）
- 函数内对**不可变对象重新赋值**，只是把局部名字绑到新对象，**调用方无感**

```python
def f_mut(xs):
    xs.append(99)          # 原地改，看得见
def f_imm(n):
    n = n + 1             # 重新绑定局部名，看不见

a = []
b = 1
f_mut(a); f_imm(b)
print(a, b)                # [99] 1
```

### 5. 不可变 ≠ 内容不能变（元组里的可变元素）

`tuple` 自身不可变（不能增删元素、不能重新赋值 `t[0]`），但**元组里引用的可变对象仍可原地改**：

```python
t = ([1, 2], 3)
t[0].append(3)            # 合法！tuple 没变，它指向的 list 变了
print(t)                  # ([1, 2, 3], 3)
```

### 6. 可哈希性（hashability）与可变性绑定

能作为 `dict` 键 / `set` 元素的对象必须**可哈希**：实现了 `__hash__` 且 `__hash__` 在生命周期内稳定、`__eq__` 一致。可变对象（list/dict/set）故意**不实现可哈希**，否则它进了字典后又被改、哈希变了，字典就找不到了。所以 `hash([1,2])` 直接 `TypeError`。

```python
d = {[1]: 1}              # TypeError: unhashable type: 'list'
d = {(1, 2): 1}           # OK，tuple 可哈希
```

## 用法

```python
# 引用共享：改一个，另一个跟着变
xs = [1, 2]
ys = xs
ys.append(3)
print(xs)                  # [1, 2, 3]

# 身份与值：is 比 id，== 比值
a = [1, 2]; b = [1, 2]
print(a == b, a is b)      # True False

# 不可变重绑定
n = 10
m = n
n += 1                     # n 指向新对象 11，m 仍指向 10
print(n, m)                # 11 10

# 函数内改可变对象会影响调用方
def add(items):
    items.append("x")
data = []
add(data)
print(data)                # ['x']
```

## 踩坑

- **共享可变状态污染**：多个用例/线程共用同一个 `list`/`dict` 入参，一个改了，别的跟着错。测试框架里这是“偶发失败”的头号来源，用深拷贝或每次新建隔离。
- **`is` 的假象**：小整数池（`-5~256`）和字符串驻留让 `256 is 256` 为真、`257 is 257` 为假；值比较永远用 `==`，别用 `is` 比数值/字符串内容。
- **误以为字符串拼接会“原地改”**：`s += c` 在循环里每轮都新建字符串，数据大时性能崩；改 `list` 拼接。
- **`tuple` 里藏 `list`**：看着不可变，其实内部可变，用作“常量配置”时会意外被改；真正想要不可变请用 `tuple` 套 `tuple`/(`frozenset`)。
- **`+=` 对不可变是重绑定，对可变是原地改**：`n += 1`（int）新建对象；`lst += [1]` 等价于 `lst.extend([1])` 原地改——同一符号两种语义，容易误判。
- **可变对象不能做 dict 键**：需要复合键用 `tuple` 包一层。

## 面试怎么答

一句话：Python 变量是名字到对象的绑定（引用语义），对象分可变/不可变——可变对象能原地改（`id` 不变），不可变对象“修改”是新建对象再重绑定。`tuple` 不可变但内部可变元素仍可改。

为什么重要：① 函数传参是“共享传参”，改可变对象对调用方可见、重绑定不可变对象不可见；② 浅拷贝只复制外层、子对象仍共享（见 [[Python 浅拷贝与深拷贝]]）；③ 可变对象不可哈希，不能做 dict 键。延伸：`is` 比 `id`、`==` 比 value；小整数池和字符串驻留会让 `is` 出现反直觉结果。
