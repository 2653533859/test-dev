# Python 浅拷贝与深拷贝

![[assets/copy-objectgraph.svg]]
*图示：赋值=引用同一对象；浅拷贝只建新外壳、内部可变对象仍共享；深拷贝递归复制出彼此独立的副本。*

> 复制一个嵌套结构时，子对象到底复制了几份？这背后是“对象引用 + 共享”的模型。理解内存里哪些是同一个对象，才能判断改一个副本会不会误伤原对象。

## 概念

先明确三条“复制”语义，它们完全不同：

### 1. 赋值 `=`

不是复制，只是**多了一个引用**，指向同一个对象。原对象和“副本”是同一个东西。

```python
a = [1, 2, 3]
b = a
print(a is b)            # True，完全同一个对象
```

### 2. 浅拷贝（shallow copy）

**新建外层容器**，但里面的元素仍是原对象的**引用**（共享）。即“壳是新做的，里面的东西还是原来的”。

常见写法：`list.copy()` `dict.copy()` `copy.copy()` `lst[:]` `list(lst)` `set(s)` `tuple(t)`。

### 3. 深拷贝（deep copy）

**递归地**把每一层子对象都复制一份，最终副本与原对象在内存里**完全独立**，互不干扰。用 `copy.deepcopy()`。

### 内存模型直觉

想象原对象是一棵树：浅拷贝是“复制了树干和一级枝，但叶子还是原来的叶子”；深拷贝是“整棵树连叶子都克隆了一份”。

```
原对象:        [ A, [B, C] ]
浅拷贝:        [ A, ────────> [B, C] ]   ← 内层 list 共享
深拷贝:        [ A', [B', C'] ]           ← 全部独立
```

### 4. 为什么会有差异

因为 Python 容器里存的不是“值”，而是“对象的引用”。浅拷贝只复制了引用这层壳，没有去递归创建被引用对象的新副本。

## 用法

```python
import copy

src = {"a": [1, 2], "b": 3}

# 浅拷贝：外层是新 dict，但 src["a"] 和 sh["a"] 是同一个 list
sh = copy.copy(src)
sh["a"].append(99)
print(src)                 # {'a': [1, 2, 99], 'b': 3}  ← 被改了！

# 深拷贝：完全独立
dp = copy.deepcopy(src)
dp["a"].append(100)
print(src)                 # {'a': [1, 2, 99], 'b': 3}  ← 不受影响

# 浅拷贝也能“切断”第一层键的绑定
sh["b"] = 30
print(src["b"])            # 3，第一层键重新绑定不影响原对象
```

要点：浅拷贝只隔离“第一层容器”和“第一层的键/索引重绑定”；一旦访问到嵌套的可变子对象并原地改，原对象跟着变。

## 踩坑

- **深拷贝大对象很慢很占内存**：递归复制整棵树，遇到几万条嵌套测试数据会明显卡顿。能浅拷贝/重建就别无脑 `deepcopy`。
- **循环引用**：`deepcopy` 内部用 `memo` 字典记录已拷贝对象，能正确处理 `a.b = a` 这种自引用，不会无限递归——这是它相对“手写递归复制”的优势。
- **不可 pickle / 含资源句柄的对象不能深拷贝**：文件对象、线程锁、数据库连接、`lambda`、部分 C 扩展对象，`deepcopy` 会 `TypeError` 或复制出无效资源；这种对象本就不该被复制。
- **`__deepcopy__` 自定义逻辑**：对象实现了 `__deepcopy__(memo)`，深拷贝会走你的逻辑；写错会让复制结果不对。
- **`copy.copy` 对不可变容器的“优化”**：对 `tuple`/`str`/`frozenset` 等不可变对象，`copy.copy` 可能直接返回自身（因为不可变不需要复制），这是预期行为，不是 bug。
- **切片 `lst[:]` 是浅拷贝**：`new = old[:]` 只复制外层，嵌套 list 仍共享（见 [[Python 列表方法与操作]]）。

## 面试怎么答

区分三级：① `=` 是多个引用指向同一对象；② 浅拷贝新建外层容器、内部元素仍是原引用（子对象共享）；③ 深拷贝递归复制所有层级，完全独立。

怎么选：只要结构里**没有嵌套可变对象**（纯一层 list of int），浅拷贝即可；有嵌套 list/dict 且需要互不影响时才用 `deepcopy`。深拷贝代价是性能和内存，还有循环引用/不可序列化对象的边界——`deepcopy` 用 memo 处理循环引用，但文件句柄/锁这类不能复制。

延伸：浅拷贝常见写法 `copy()`/`[:]`/`list(x)`；深拷贝 `copy.deepcopy()`。判断“改副本是否影响原对象”就看你改的是不是共享的子对象。
