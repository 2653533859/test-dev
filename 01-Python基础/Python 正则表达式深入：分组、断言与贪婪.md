# Python 正则表达式深入：分组、断言与贪婪

![[assets/regex-backtrack.svg]]
*图示：正则回溯引擎——贪婪量词先尽可能匹配再回溯；嵌套量词 `(a+)+$` 配不可匹配结尾会指数级回溯（ReDoS），须避免。*

## 概念：正则是一个「匹配引擎」，Python 用 `re` 模块暴露

正则（regular expression）用一套元字符描述「字符串模式」。Python 的 `re` 模块基于**回溯（backtracking）引擎**：它尝试匹配，遇到分支/量词就「试一条路，不行就回退换另一条」。理解回溯是理解正则性能与陷阱的核心（基础用法见 [[Python 标准库：re 与 datetime]]）。

### 先看基础回顾

```python
import re
re.match(r"\d+", "123abc")        # 从开头匹配，返回 <Match>
re.search(r"\d+", "abc123")       # 扫描整个串找第一个
re.findall(r"\d+", "a1b22c333")   # ['1', '22', '333']
re.fullmatch(r"\d+", "123")       # 整个串必须匹配
re.sub(r"\d", "#", "a1b2")        # 'a#b#'
```

`r"..."` 原始字符串很关键：避免把 `\d` 里的反斜杠被 Python 字符串先转义掉。

## 用法一：分组 `()` —— 捕获与引用

```python
import re

m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "日期 2026-07-31")
print(m.group(0))       # 2026-07-31  （整个匹配）
print(m.group(1))       # 2026         （第 1 个捕获组）
print(m.group(2, 3))    # ('07', '31')
print(m.groups())       # ('2026', '07', '31')

# 命名分组：可读、可按键取
m = re.search(r"(?P<year>\d{4})-(?P<month>\d{2})", "2026-07")
print(m.group("year"))  # 2026
print(m.groupdict())    # {'year': '2026', 'month': '07'}
```

分组把「一段子模式」圈起来，匹配后能用 `group(n)` 单独取出，适合从文本里提取结构化字段（日志、日期、URL）。

### 反向引用：匹配「重复出现的内容」

```python
import re
# \1 引用第 1 组的匹配结果：找相邻的重复单词
m = re.search(r"\b(\w+)\s+\1\b", "hello hello world")
print(m.group())        # 'hello hello'
```

`\1` 表示「这里必须和第一组匹配到的文本一模一样」。

### 非捕获分组 `(?:...)`

```python
import re
# 只想分组用于量词，不需要捕获内容时用 ?:
m = re.search(r"(?:ab)+c", "ababc")
print(m.groups())       # ()  —— 没有捕获组
```

`(?:...)` 分组但不「占用」group 编号，能省内存、也让 `group(n)` 编号更干净。

## 用法二：贪婪 vs 非贪婪

这是正则最经典的坑。`* + ? {n,}` 默认是**贪婪（greedy）**：尽可能多匹配。

```python
import re
s = "<a>1</a><b>2</b>"

# 贪婪：.* 一路吃到最后一个 </...> 才停
print(re.search(r"<.*>", s).group())       # <a>1</a><b>2</b>

# 非贪婪：.*? 一遇到第一个 > 就停
print(re.search(r"<.*?>", s).group())      # <a>
```

**原理**：贪婪量词先尽可能向右吞，吞到不能匹配整体模式了再「吐」回来（回溯）；非贪婪量词（`*?` `+?` `??`）相反，先尽量少匹配，不够再扩展。非贪婪不是「更快」，有时反而更多回溯。

> 提取标签内容更稳妥的做法是直接写 `[^>]*`（除 `>` 外的任意字符），避免依赖贪婪/非贪婪的微妙行为。

## 用法三：断言（零宽断言，lookaround）

断言**只检查「某位置前后是否满足条件」，不匹配消耗字符**，所以叫「零宽」。

```python
import re
s = "price=100, count=5"

# 肯定前瞻 (?=...)：匹配后面跟着 =数字 的单词
print(re.findall(r"\w+(?==\d)", s))        # ['price', 'count']

# 否定前瞻 (?!...)：匹配后面【不】是数字的单词边界
# 肯定后顾 (?<=...)：前面是 $ 的数字
print(re.findall(r"(?<=\$)\d+", "cost $99 tax $5"))   # ['99', '5']

# 否定后顾 (?<!...)：前面不是 $ 的数字
print(re.findall(r"(?<!\$)\d+", "cost $99 tax 5"))    # ['99', '5']（空格前的5也匹配）
```

四种断言：

| 写法 | 名称 | 含义 |
|------|------|------|
| `(?=X)` | 肯定前瞻 | 右边紧跟 X |
| `(?!X)` | 否定前瞻 | 右边不跟 X |
| `(?<=X)` | 肯定后顾 | 左边紧贴 X |
| `(?<!X)` | 否定后顾 | 左边不贴 X |

**后顾限制**：Python 的 `re` 要求后顾里的模式长度固定（不能用 `*`/`+` 这种不定长），否则报 `look-behind requires fixed-width pattern`。

## 用法四：编译与标志

```python
import re
# 多次使用同一正则时先 compile，省去重复解析
pattern = re.compile(r"\d+", re.IGNORECASE)
pattern.findall("A1 b2 C3")

# 常用标志
re.IGNORECASE / re.I     # 忽略大小写
re.MULTILINE  / re.M     # ^ $ 匹配每行首尾
re.DOTALL    / re.S     # . 也匹配换行符
re.VERBOSE   / re.X     # 允许正则里加注释和空白
```

`re.VERBOSE` 让复杂正则可读：

```python
pattern = re.compile(r"""
    (?P<year>\d{4}) - (?P<month>\d{2}) - (?P<day>\d{2})
""", re.VERBOSE)
```

## 踩坑

1. **忘了原始字符串 `r""`**：`"\d"` 里 `\d` 被 Python 转义，正则收到错误模式。一律用 `r""` 写正则。
2. **贪婪匹配吞太多**：`"<.*>"` 跨标签匹配。改用非贪婪 `.*?` 或 `[^>]*`。
3. **ReDoS（正则拒绝服务）**：灾难性回溯。如 `(a+)+$` 对 `"aaaaaaaaaaaaaaaaaaaaaaaaaaaaX"` 会指数级回溯，卡死服务。对外来正则/输入要限制长度或避免嵌套量词。
4. **后顾用了不定长**：`(?<=a*)` 报错。后顾必须固定宽度，改用前瞻或重写。
5. **`match` 只从开头**：`re.match(r"\d", "a1")` 返回 None（应从 `search`）。很多人误以为 match 是「是否包含」。
6. **`group` 在 None 上调用**：没匹配到时 `search` 返回 None，直接 `.group()` 会 `AttributeError`。先判空。
7. **捕获组太多拖慢**：用非捕获 `(?:)` 替代不需要的捕获组。

## 面试怎么答

**Q：贪婪和非贪婪的区别？**
A：贪婪量词（`*`、`+`）默认尽量多匹配，不够再回溯；非贪婪（`*?`、`+?`）尽量少匹配，不够再扩展。提取标签内文本用 `[^>]*` 比依赖非贪婪更稳。

**Q：什么是零宽断言？**
A：断言只检查某位置前后是否满足条件，不消耗字符。分前瞻 `(?=)`/`(?!)` 和后顾 `(?<=)`/`(?<!)`。常用来「匹配 X 但只在它前面是 Y 时」，且不把 Y 纳入结果。

**Q：什么是 ReDoS？**
A：正则的回溯引擎在遇到嵌套量词（如 `(a+)+$`）加恶意输入时，会产生指数级回溯，CPU 被占满导致服务不可用。对外来输入/正则要限制或避免此类模式。

**Q：为什么要 compile 正则？**
A：同一正则被反复使用时，`re.compile` 预编译成 Pattern 对象，省去每次重新解析模式的开销，性能更好、也可复用一个对象。单次使用差别不大。
