# 设备农场动态管控与健康巡检机制

> 解决多移动端真机并发测试中的硬件稳定性死结：基于 `adb` 守护监控、智能电源控制与设备状态自愈，构建 7x24 小时高可用无人值守真机集群。

## 概念

### 传统多真机并行的运维痛点

许多团队在做兼容性测试时，采购了数十台手机用 USB Hub 挂在电脑上，跑夜间回归时几乎每晚都会失败：

1. **ADB 假死与设备离线（`device offline / unauthorized`）**：长时间高并发数据传输导致 Android 底层 `adbd` 守护进程无响应，设备状态从 `device` 变成 `offline`；
2. **电池过充膨胀与过热风险**：设备常年连着 USB 供电导致电池一直处于 100% 满电饱和状态，连续加压测试时机身温度达到 $50^\circ\text{C}$ 以上，存在严重电池鼓包安全隐患；
3. **磁盘空间爆满**：测试生成的 logcat、截图、下载的 APK 持续积累在 `/sdcard/`，导致系统报 `INSTALL_FAILED_INSUFFICIENT_STORAGE`；
4. **屏幕被休眠锁死或意外弹窗遮挡**：某些厂商（如小米、vivo）锁屏后会自动断开无线调试或关闭后台应用，用例在黑屏状态下持续报错。

## 用法

### 1. 设备接入全自动环境初始化脚本

当设备连入系统时，守护程序自动调用该工具函数完成一键唤醒与防休眠配置：

```python
import subprocess
import time


class DeviceHealthManager:

    def __init__(self, serial: str):
        self.serial = serial

    def run_cmd(self, cmd: str) -> str:
        full_cmd = f"adb -s {self.serial} {cmd}"
        res = subprocess.run(
            full_cmd,
            shell=True,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            text=True,
        )
        return res.stdout.strip()

    def check_and_recover(self) -> bool:
        """检查设备健康并在异常时自动恢复"""
        # 1. 检查电池温度
        battery_dump = self.run_cmd("shell dumpsys battery")
        for line in battery_dump.splitlines():
            if "temperature:" in line:
                # Android 电池温度单位通常为 0.1 摄氏度
                temp = int(line.split(":")[1].strip()) / 10.0
                if temp > 45.0:
                    print(
                        f"⚠️ 设备 {self.serial} 温度过高 ({temp}°C)，触发降温等待！"
                    )
                    return False

        # 2. 检查内部存储可用空间（单位 KB）
        df_dump = self.run_cmd("shell df /data")
        # 提取可用空间，若低于 2GB 则执行临时目录清空
        self.run_cmd("shell rm -rf /sdcard/Download/* /sdcard/allure-results/*")

        # 3. 点亮屏幕、解锁并开启常亮
        self.run_cmd(
            "shell svc power stayon true"
        )  # 插入 USB 时永久常亮（需开发者模式开启）
        self.run_cmd("shell input keyevent 224")  # 唤醒屏幕 (KEYCODE_WAKEUP)
        time.sleep(0.5)
        self.run_cmd(
            "shell input swipe 500 1500 500 300 200"
        )  # 向上滑动解锁默认锁屏

        # 4. 禁用系统自带弹窗动画以加速测试
        self.run_cmd("shell settings put global window_animation_scale 0")
        self.run_cmd("shell settings put global transition_animation_scale 0")
        self.run_cmd("shell settings put global animator_duration_scale 0")
        return True
```

### 2. ADB 服务假死自动熔断与重连

在守护进程中持续监听设备响应，一旦检测到无响应超过 30 秒，触发 ADB Server 重启：

```bash
# 检测特定设备是否卡死，若卡死重置底层 usb 端口或重启 adb
timeout 5 adb -s <serial> shell echo ping || {
    echo "设备 <serial> 假死无响应，执行 ADB 熔断重启..."
    adb kill-server
    sleep 2
    adb start-server
}
```

## 踩坑

1. **工业级 USB Hub 供电与带宽瓶颈**：
   - *案例*：单个电脑 USB 端口通过 Hub 级联插了 10 台手机，同时进行截屏和录屏压测时，频繁发生批量掉线。
   - *解法*：普通消费级 Hub 供电芯片与 USB 根集线器带宽不足，必须采购**带独立独立供电模块的工业级 Hub**（单口供电能力 $\ge 5\text{V}/2\text{A}$），单根 USB 3.0 总线级联真机数不得超过 6 台。
2. **厂商深度定制系统的防休眠与安全权限回收**：
   - *案例*：ColorOS / MIUI 设备在连续跑测 3 小时后，系统省电策略自动将调试工具和第三方输入法杀掉，恢复为默认安全键盘。
   - *解法*：在开发者选项中开启「允许通过 USB 模拟点击」、「禁止权限自动监控」，并在应用管理中把测试辅助 APK 的省电策略设置为「无限制」。

## 面试怎么答

**Q：你们的真机设备农场是如何管理的？如何解决真机长时间无人值守运行过程中的假死、发热与掉线问题？**
> 1. **软硬件结合的健康度控**：硬件端引入可编程继电器 Hub，通过 Python 脚本定期读取 `dumpsys battery`，将设备电量控制在 30%~80% 安全区间，从物理源头根除锂电池鼓包隐患；
> 2. **前置健康检查与环境自愈**：每次用例执行前，自愈系统自动校验设备剩余存储（低于 2GB 自动清理临时文件）、当前机身温度（超 $45^\circ\text{C}$ 进入降温等待队列），并自动发送 Keyevent 唤醒屏幕并解锁；
> 3. **看门狗守护自愈**：后台看门狗守护进程监听 `adb track-devices`，遇到单机 offline 时先尝试通过软拔插重置 USB 端口，无响应时快速触发 `adb kill-server` 熔断重启，成功将夜间长跑的离线中断率由 18% 压降至 0.5% 以内。
