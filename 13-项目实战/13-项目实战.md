# 13-项目实战

端到端练手项目。前面 11 个模块是零件，这里是把零件装成能写进简历的东西。

## 目录约定

每个项目一个子目录，内含：

```text
项目名/
├── 项目名.md        项目说明（背景、目标、技术选型、架构、成果、踩坑复盘）
├── 设计与实现/       拆解笔记
└── code/            示例代码（如需完整工程，另建独立仓库并在说明里链接）
```

代码量大的项目建议单独开 Git 仓库，本目录只留说明与设计笔记 + 仓库链接，避免知识库变成代码仓库。

## 建议的练手项目

按难度递进，每完成一个都要能讲清「解决了什么问题、量化收益是什么」：

1. **接口自动化框架** —— pytest + requests + YAML 数据驱动 + Allure + 多环境配置。最该先做的一个，面试问得最细。
2. **Web UI 自动化用例集** —— Playwright + Page Object，选一个公开站点或自己搭的靶站，重点是稳定性治理。
3. **CI 流水线打通** —— 把前两个项目接进 Jenkins 或 GitHub Actions，做到提交即触发、失败即通知。
4. **App 自动化用例集** —— Appium + 一个开源 App，附一份移动端专项测试方案。
5. **性能测试报告** —— 对自己搭的服务做一轮压测，输出建模、执行、瓶颈定位、调优前后对比的完整报告。
6. **测试平台** —— FastAPI 或 Django + Vue，实现用例管理、执行调度、报告展示。工作量大，是简历里的加分项。
7. **Mock 服务 / 造数工具** —— 小而实用，能体现「用工具解决团队痛点」的思路。

## 复盘要求

项目说明里必须写清这几项，否则面试时讲不出深度：

- 为什么选这个技术方案，放弃了什么替代方案
- 遇到的最大技术难点和解决过程
- 可量化的收益（回归时间从 X 降到 Y、覆盖接口数、拦截线上问题数）
- 现在回头看有什么设计缺陷
