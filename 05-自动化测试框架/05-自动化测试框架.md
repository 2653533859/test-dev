# 05-自动化测试框架

其他自动化方向（接口 / Web / App）共用的底座。pytest 是重点，框架设计能力是测开与手工测试的分界线。

## 学习目标

- 熟练使用 pytest 的 fixture、参数化、标记、插件体系
- 能从零搭一套分层框架：用例层 / 业务层 / 接口或页面层 / 工具层 / 配置层 / 数据层
- 输出可读的测试报告，接入 CI 后能让别人看懂失败原因
- 能解释自己框架的设计取舍，而不只是「照着教程搭的」

## 计划覆盖的知识点

- 测试理论：测试用例设计方法（等价类、边界值、场景法、正交）、分层测试模型与测试金字塔
- unittest：`TestCase`、`setUp` / `tearDown`、`TestSuite`、断言方法
- pytest 核心：用例发现规则、断言与 `assert` 重写、`conftest.py` 作用域
- fixture：四种作用域、`yield` 前后置、`autouse`、fixture 间依赖、参数化 fixture
- 参数化：`@pytest.mark.parametrize`、`ids`、多参数笛卡尔积
- 标记与筛选：自定义 mark、`-k` / `-m`、`skip` / `skipif` / `xfail`
- 常用插件：`pytest-html`、`allure-pytest`、`pytest-xdist` 并行、`pytest-rerunfailures` 失败重跑、`pytest-ordering`
- 框架设计：目录分层、配置与环境隔离（多环境切换）、日志封装、断言封装、数据驱动（YAML / Excel / JSON）、公共工具层
- 报告：Allure 的分组与附件、失败截图与日志挂载

## 常考点

- fixture 与 `setUp` 的区别，fixture 四种作用域分别什么时候用
- `conftest.py` 的查找规则，多层目录下如何生效
- 用例之间有依赖怎么办（为什么应该避免，实在避不开怎么处理）
- 并行执行时数据冲突和 fixture 重复初始化怎么解决
- 你的框架分了几层，每层职责是什么，为什么这样分
