# 敏感信息泄露与传输配置测试

> 范围约束：以下验证只在自己有权限的测试环境/靶场进行，不针对无授权目标，重点在「发现与报告」。

## 概念

敏感信息泄露不是某一种漏洞，而是一类**「本不该暴露的东西被暴露了」**的问题，常见于：接口返回多余字段、日志打印明文、源码/备份文件可直接下载、错误页泄露堆栈、传输层配置过弱。它的危害是「给攻击者送弹药」——拿到手机号、内部路径、密钥片段，后续越权/注入就更容易。

传输配置问题则集中在 HTTPS/TLS：用了过期协议（TLS1.0/1.1）、弱密码套件、证书校验被关掉，导致中间人可窃听或篡改。

## 用法

几个日常可做的检查点（自有环境）：

```text
1. 接口返回瘦身：用普通用户调详情接口，看响应体是否夹带了
   管理员字段、其他用户数据、内部 debug 信息
2. 日志审查：在测试环境制造一次请求，翻服务日志，确认没有
   明文密码/身份证/手机号被 print 出来
3. 备份/源码暴露：尝试 /backup/、/.git/、/config.php.bak、
   /WEB-INF/ 等常见路径，看是否可直接下载
4. 错误页：故意触发 500，看是否回显堆栈/SQL/绝对路径
5. 传输层：用 SSL Labs 或 nmap 脚本查目标支持的 TLS 版本与套件，
   确认禁用 TLS1.0/1.1、启用 HSTS
```

## 踩坑

- **只测「成功路径」忽略响应膨胀**：接口正常返回时数据干净，但错误分支可能把内部对象整个序列化出去——要专门测异常路径。
- **以为 HTTPS 就安全**：没开 HSTS 会被降级劫持，套件过弱等于明文，证书校验被框架「为了方便」关掉更是灾难。
- **日志脱敏只做了一半**：只脱敏了接口入参，忘了异步任务、网关访问日志里还有明文。
- **把 `.git` 暴露当小事**：源码里往往有数据库密码、内网地址，是高危信息源。
- **测试环境结论直接套生产**：测试环境可能关了脱敏方便调试，不能据此判断生产安全。

## 面试怎么答

- **怎么发现敏感信息泄露？** 多角度看：响应体是否超量返回、日志是否明文、备份/源码/错误页是否可访问、传输层配置是否够强，逐类排查。
- **HTTPS 一定安全吗？** 不一定。还要看 TLS 版本/套件强度、是否启用 HSTS 防降级、服务端是否真的校验了证书（客户端关闭校验等于裸奔）。
- **接口返回多余字段算漏洞吗？** 算信息泄露，尤其当多余字段含他人数据或权限信息时，应让后端做响应字段白名单。
