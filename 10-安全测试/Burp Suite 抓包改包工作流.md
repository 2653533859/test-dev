# Burp Suite 抓包改包工作流

> 范围约束：以下工作流只用于自有测试环境或授权靶场（DVWA、Juice Shop、pikachu），不针对无授权目标。

## 概念

Burp Suite 是 Web 安全测试的中间人代理。它把浏览器流量「拦在中间」，让你**看得到每一个请求/响应，并能手动改写后再发出去**——这正是验证越权、参数篡改、逻辑漏洞的核心手段。四个最常用的模块：

- **Proxy**：拦截并转发流量，是入口。
- **Repeater**：把某个请求单独拎出来，反复改、反复发，方便精调。
- **Intruder**：把某个参数做成变量，自动批量替换（遍历 id、枚举验证码等）。
- **Decoder / Comparer**：编解码、对比两次响应差异。

## 用法

标准工作流：

```text
1. 浏览器把代理指向 Burp（127.0.0.1:8080），并信任 Burp 的 CA（否则 HTTPS 抓不到）
2. Proxy -> Intercept 开启，操作业务，请求被拦住
3. 在拦截框里改参数（如把 orderId 改成别人的、把 amount 改成 0.01），Forward 放行
4. 把可疑请求 Send to Repeater，脱离业务流程反复重放验证
5. 需要批量时 Send to Intruder，设 Payload 跑遍历/枚举
```

验证越权的典型手法（仅自有环境）：拦截「查看订单」请求，把 URL 里的 `orderId` 改成不属于当前账号的 id，看响应是否仍返回 200 与数据。

## 踩坑

- **HTTPS 没装 Burp CA**：拦截到的都是 `Certificate_Unknown`，流量过不去。要先在浏览器信任 Burp 自签根证书（仅测试浏览器，用完移除）。
- **只改了参数没看响应**：改包后必须对比响应——返回 200 但业务报错，和返回 200 且真返回了他人数据，性质完全不同。
- **Intruder 把正常接口打挂**：批量遍历要有节奏和上限，避免把自有测试环境打成 DoS；生产环境绝对不做。
- **忽略了签名/时间戳**：很多接口对请求做了签名（`sign`）或带时间戳，单纯改参数会被服务端拒绝——要先理解签名逻辑（见 [[接口签名鉴权与 sign 计算]]）。
- **混淆靶场与生产**：靶场验证的是「原理可复现」，生产是否受影响要看实际鉴权代码。

## 面试怎么答

- **Burp 在你的测试里主要干什么？** 当中间人拦截并改写请求，验证越权、参数篡改、重放这类逻辑漏洞；Repeater 精调、Intruder 批量。
- **为什么扫描器扫不出逻辑漏洞？** 越权/并发超卖依赖业务上下文和合法身份的多次操作，通用扫描器没有业务语义，只能靠人工抓包构造。
- **HTTPS 为什么抓不到、怎么解决？** 因为 TLS 加密，需把 Burp 的根证书装进测试浏览器信任库，才能解密查看。
